KEY FINDING
────────────────────────────────────────────────────────────────────────────
  counter_k is keyed by KEYSET only (counterK.ts:15) and is NOT reset on
  deleteWallet() (storage.ts:226-240) or importSeed() (seed.ts:99-147). A new
  seed inherits the stale counter → mint/swap start at a non-zero counter →
  counters 0..stale-1 are never signed (GAP).

  restore.ts has two assumptions that break on a GAP:
    (1) restore.ts:102-103  response.signatures[i] → prepared[i]
        — Nutshell returns a FILTERED list (only signed outputs, aligned to
          response.outputs, NOT to the request). With a gap the index no longer
          matches, so signatures are unblinded with the WRONG blinding factor
          and assigned the WRONG secret → garbage proofs.
    (2) restore.ts:176       lastNonEmptyCounter = counter + proofs.length
        — assumes signed counters are contiguous from `counter`. With a gap it
          undercounts (2 instead of 3 above), so the next mint re-derives a
          counter that is still unsigned at the mint.

  In the CLEAN (no-gap) flows the counter reconstructs correctly and the
  change/swap proofs ARE recovered — so the A2/A4 loss requires the gap, whose
  trigger is the counter_k lifecycle bug (not NUT-9, which DOES return the
  melt-change/swap signatures — see the verbatim bodies in repro-run.log).
