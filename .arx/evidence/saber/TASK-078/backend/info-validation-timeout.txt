F-044 — /v1/info Validation — Timeout Handling
=================================================

Implementation:
  const TIMEOUT_MS = 5000;  // 5 seconds
  const timeoutPromise = new Promise<never>((_, reject) => {
      setTimeout(() => reject(new DOMException('Validation timeout', 'AbortError')), TIMEOUT_MS);
  });
  
  const result = await Promise.race([
      discoverMintEndpoints(cleaned),
      timeoutPromise
  ]);

Timeout Flow:
  1. User enters mint URL → clicks 'Validate'
  2. Promise.race starts: discoverMintEndpoints vs 5s timeout
  3. If discoverMintEndpoints completes first → normal flow (success/error)
  4. If 5s elapses first → DOMException('AbortError') thrown
  5. Catch block detects AbortError → 'ไม่พบ mint — ตรวจสอบ URL (หมดเวลา 5 วินาที)'
  6. Error displayed in modal input error field
  7. User can retry with different URL

Graceful Degradation:
  ✓ No crash — error caught and displayed
  ✓ Modal stays open — user can edit URL and retry
  ✓ validating = false after timeout — UI returns to normal state
  ✓ Cancel button still works — user can close modal

Note:
  discoverMintEndpoints uses fetchFromMint with default 15s timeout internally.
  Our 5s timeout fires BEFORE the internal 15s timeout, providing faster UX feedback.
